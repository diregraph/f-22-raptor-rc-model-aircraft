# ArduPilot for the F-35B model

The aircraft flies on stock **ArduPlane 4.7.2** (QuadPlane) on an STM32 H7 board. No firmware fork:
the unusual parts of this layout are handled by two Lua scripts. The same files fly the simulation
and the real board.

| File | What |
|---|---|
| `f35b.parm` | Parameters for the aircraft (load on the board and in SITL) |
| `sitl.parm` | Simulation-only overrides (arming checks off, sim tail trims). Never load on the board |
| `scripts/f35b_frame.lua` | Motor layout for `Q_FRAME_CLASS 15`: lift fan, main fan, roll pair. Generated by `node tools/ardupilot-gen.mjs` from `site/js/spec.js` |
| `scripts/nozzle_3bsm.lua` | Link to `firmware/nozzle/nozzle_3bsm.lua`: sends deflection and yaw to the nozzle board |

## Outputs

| Out | Function | Goes to |
|---|---|---|
| 1, 2 | 77, 78 elevon left/right | all-moving tails |
| 5–8 | 33–36 motors 1–4 | ESCs: lift fan, main fan, roll left, roll right |
| 9 | 41 motor tilt | nothing plugged in: the nozzle script reads it |
| 10, 11 | 94, 95 script 1/2 | nozzle board: deflection (1000-2000 us = 0-100 deg), yaw swing (1000-2000 us = -20..+20 deg) |
| 12 | 29 landing gear | the three leg servos on one Y lead |

## How it works

- **Hover:** the four fans are mixed by the frame script. Roll and pitch factors give a pure moment
  with no change in lift; throttle factors share the lift as the hover trim does (lift fan and roll
  pair at 60%, main fan at about 25%). Yaw factors are zero: fan torque is too weak to steer with.
- **Hover yaw:** the nozzle script reads `motors:get_yaw()` and swings the bent jet sideways.
- **Transition:** continuous tilt on motor 2 only (`Q_TILT_MASK 2`). ArduPilot holds the nozzle at
  25° from aft (`Q_TILT_MAX 65`) until 16 m/s, then swings it fully aft and stops the lift fans.
- **Forward flight:** the all-moving tails as elevons. No rudder.

## Simulation

The physics is `site/js/sim.js` (the same model the 3D page flies), run in Node by
`tools/sitl-bridge.mjs` over ArduPilot's JSON simulator interface.

```
git clone --branch Plane-4.7.2 --recurse-submodules https://github.com/ArduPilot/ardupilot.git ~/ardupilot
cd ~/ardupilot && ./waf configure --board sitl && ./waf plane      # about 4 minutes
pip install pymavlink pexpect 'empy==3.3.4'
cd <this repo>
python3 tools/sitl-run.py all          # hover, mission, gust, weak-roll-motor; about 10 minutes at 4x speed
python3 tools/sitl-summary.py          # scores them and writes site/analysis/sitl/summary.json
```

Each flight lands in `site/analysis/sitl/<scenario>.json`; the 3D page replays it (Fly it, then
"Watch ArduPilot fly", or `index.html?replay=mission&t=30`) and `/analysis.html` charts it.

To fly by hand instead, run `node tools/sitl-bridge.mjs` and start
`build/sitl/bin/arduplane --model JSON:127.0.0.1 --defaults ardupilot/f35b.parm,ardupilot/sitl.parm`
from a folder holding a `scripts` link to `ardupilot/scripts`, then connect Mission Planner or
QGroundControl to TCP 5760.

## Before the first real flight

- Measure thrust on the stand and update `spec.js`; re-run `node tools/ardupilot-gen.mjs` and SITL.
- Set the nozzle motor and encoder directions and check the homing stops on the bench (`firmware/nozzle/Nozzle3BSM.h`,
  `cfg.dir` and `cfg.stop`; docs/ducted-propulsion.md, test plan steps 6 and 7).
- Check every output with propellers off (Mission Planner motor test, servo output page).
- Tail trims are learnt in flight (`SERVO_AUTO_TRIM 1`); the sim's are in `sitl.parm` only.
- Without GPS, fly QHOVER and FBWA only: QLOITER and AUTO need a position fix.
